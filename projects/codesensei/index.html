CodeSensei

Agentic AI · Built

A five-agent code intelligence system with synthesized cognitive reviews

React TypeScript Node.js Gemini D3.js

01 · Overview

Five specialists walk into a codebase

CodeSensei is a multi-agent code intelligence system. Instead of asking one model to review everything at once, it splits the job across five specialized agents — each with a narrow question to answer — and a synthesizer that turns their combined findings into one coherent result.

Monolithic prompts fail on large codebases because code analysis demands contradictory perspectives: the structural engineer wants clean abstractions; the runtime engineer cares about memory allocations; the security engineer views every input with suspicion. Splitting these into distinct agent roles produces deeper, non-generic reviews.

02 · Architecture

From raw source to synthesized review

The five agents inspect the repository in parallel. Their findings fan into an SVG convergence manifold that feeds the Synthesizer for deduplication and resolution.

03 · The Five Agents

Five angles on the same source

01 · Structure Agent

Parses the codebase into an AST and maps its skeleton: how modules, classes, and inheritance graphs interact. Answers: what is this code structurally?

02 · Behavior Agent

Traces control flow and data flow end to end. Answers: what does this code actually do when invoked — including undocumented edge branches?

03 · Risk Agent

Flags unhandled exceptions, race conditions, nullability pitfalls, and transaction boundaries. Answers: where will this break under stress?

04 · Execution Agent

Follows runtime execution traces: allocations, tight loops, hot paths. Answers: what happens in practice, not just in static theory?

05 · Impact Agent

Maps callers, downstream dependents, database models, and public contracts. Answers: if this line changes, what else across the system should worry?

04 · The Synthesizer

Why the convergence step matters

When independent agents review code, conflicts are inevitable. Structure might recommend splitting a 200-line function into three helper classes; Risk might warn that splitting adds indirection to an already fragile concurrency lock.

The Synthesizer treats conflicts as first-class problems. It builds a conflict matrix, weighs priority based on failure severity, and merges overlapping observations into a crisp bulleted summary.

05 · Workflow

How an analysis actually runs

  1. Ingestion: Repository source parsed into AST representations and module dependency matrices.
  2. Parallel Dispatch: The 5 specialized agent prompts dispatch with structured JSON schema constraints.
  3. Synthesizer Reconciliation: Discrepancies mapped into bipartite conflict graphs and deduplicated.
  4. Interactive Report: D3.js knowledge graph visualizes blast radius alongside prioritized fixes.

06 · Example Walkthrough

Tracing bulk_update without transactions

// Candidate function submitted for review: 
def bulk_update(users, patch):
    out = []
    for u in users:
        u = {**u, **patch}
        out.append(u)
    save_all(out)        # one transaction? per item?
    return out

Synthesized Findings Trace:

1. [call] bulk_update(users[0:2], {"active": True})

2. [loop] iter 1 · dict-merge · ok

3. [loop] iter 2 · dict-merge · ok

4. [call] save_all(out) → 2 writes, no transaction boundary

5. [risk] Partial failure mid-write leaves database in corrupt, inconsistent state.
