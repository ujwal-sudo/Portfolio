LedgerLens

FinTech AI · Built

An AI-powered financial investigation workflow and forensic reconciliation pipeline

FastAPI SQLite Streamlit

01 · Overview

From mismatched ledgers to closed cases

LedgerLens is an AI-powered financial investigation system built as a pipeline: reconcile the books, detect what's unusual, test it against policy, bundle it into cases, and let a ReAct-style agent investigate — with a hypothesis engine making the whole loop smarter than guesswork.

Financial investigations often suffer from two extremes: rigid rule-based systems that flood compliance teams with false positives, or unconstrained LLMs that hallucinate numbers. LedgerLens pairs deterministic mathematical reconciliation with an iterative, auditable reasoning agent.

03 · Stage by Stage

Deep dive into the pipeline mechanics

01 · Reconciliation Engine

The foundation: ingest ledgers and bank statements, align transactions across sources, and expose every delta. Nothing downstream means anything if the books don't reconcile first.

02 · Anomaly Detector

Once balances agree, attention turns to behavior: statistical outliers, unusual sequences, amounts and timing that don't fit history. This stage decides what deserves a second look.

03 · Policy Engine

Flags get tested against policy — thresholds, segregation-of-duties rules, compliance constraints. An anomaly that violates policy becomes a candidate case; one that doesn't gets logged and released.

04 · Case Management

Evidence, timeline, and scope bundle into a case with state — open, escalated, closed. A human or an agent picks up a case and immediately sees complete historical context.

05 · Hypothesis Engine

For each open case, generate ranked candidate explanations: duplicate entry, timing mismatch, processing error, or deliberate evasion. Hypotheses make investigation a targeted search instead of a fishing trip.

06 · ReAct-Style Investigation Agent

The agent works the case in a reason → act → observe loop: query the database, check a hypothesis against it, request more context, and either close the case with an explanation or hand it up with a structured audit trail.

04 · Technical Implementation

Deterministic rules before non-deterministic agents

A core architecture decision in LedgerLens is keeping LLMs out of basic arithmetic. Reconciliation, statistical deviations, and rule checks are implemented in deterministic Python and SQL.

The ReAct agent is invoked only once a case is formed and hypotheses need testing against historical evidence. Every tool call and observation is recorded to an immutable SQLite audit log table.
