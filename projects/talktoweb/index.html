TalkToWeb

Automation · Built

Natural-language browser automation and multi-step web workflow execution

LangChain Gemini Playwright FastAPI

01 · Overview

Talk to the web; it talks back with data

TalkToWeb translates natural-language instructions into real browser workflows. The interesting problem isn't clicking buttons — it's the loop around the clicking: planning, observing, noticing that the page didn't do what you expected, and deciding what to try next.

Most browser bots break the moment a dynamic modal appears or a CSS selector mutates. TalkToWeb treats the DOM as an environment state in an interactive reinforcement/planning loop.

02 · The Flow

From intent to DOM execution

  1. 01 · The Instruction

    Everything starts as plain language: "Summarize the latest release notes on blog.example.com", with no hardcoded script.

  2. 02 · Planning & Skill Selection

    LangChain + Gemini decompose intent into a step-by-step sequence: navigate → find search field → type query → extract result cards.

  3. 03 · Browser Actions

    Headless Playwright drives the browser: waits for network idle, locates semantic nodes, dispatches human-like keystrokes.

  4. 04 · Observation

    Live accessibility tree and sanitized DOM fragments feed back into the agent to verify success.

  5. 05 · Result & Recovery Loop

    Structured data emitted as JSON. If an action fails (e.g. element hidden), an error recovery loop replans alternative selectors.

03 · Browser Actions

Primitive action vocabulary

goto(url)

Navigate to URL with configurable network-idle timeouts.

click(selector, role)

Click elements using ARIA role matching and text heuristics.

fill(selector, text)

Type text into inputs with pre-clear and post-change verification.

extract(schema)

Extract structured JSON schema rows directly from table/card trees.

wait(condition)

Synchronize on DOM mutations, navigation events, or network idle cycles.

04 · Error Handling

Resilient failure recovery

When a web step fails, TalkToWeb avoids crashing immediately. Instead, it captures the current accessibility tree, passes the exception reason back to the planner, and asks:

"Action click('button#checkout') timed out. Observed current DOM: modal '#cookie-consent' is covering viewport. Remedy: dismiss '#cookie-consent' first."

This dynamic remediation handles over 80% of transient UI obstacles without human intervention.

05 · Status

Implemented vs Experimental capabilities

Implemented & Verified
  • Single-tab browser navigation & session persistence
  • Semantic selector discovery via accessibility trees
  • Form filling, select options, and button triggering
  • Structured tabular data extraction
  • Automatic modal and cookie banner dismissal
Active Research & Experimental
  • Multi-tab state synchronization
  • HTML5 Canvas and WebGL interactive extraction
  • Audio / visual CAPTCHA recovery mechanisms
  • Complex dragging & drag-and-drop workflows
