Pythia-160M — Architecture & Training Stack

160M Params · PyTorch Scratch

Core Architecture: Pythia-160M is a 12-layer decoder-only transformer implemented completely from scratch in PyTorch, avoiding high-level abstractions to master every mathematical component of modern LLMs. It replaces standard multi-head attention with Grouped-Query Attention (GQA), pairing 12 Query heads with 2 Key-Value heads to reduce KV-cache memory bandwidth by 6× during code generation. Position encoding is handled via Rotary Positional Embeddings (RoPE) ($\theta = 10,000$) for superior sequence length generalization.

Training Objectives & Tokenizer: Combines Next-Token Prediction (NTP) with Fill-in-the-Middle (FIM) at a 50/50 split using custom Sentinel tokens (`<PRE>`, `<SUF>`, `<MID>`) to enable docstring and function body completion. The tokenizer is a custom 32,768-vocab BPE engine with explicit multi-whitespace tokens to eliminate Python indentation fragmentation.

Key Engineering Hurdles Solved

01 · Indentation Token Bloat

Standard tokenizers split 4-space indentation into 4 separate tokens. Solved with dedicated whitespace run tokens, saving 24% context space on Python files.

02 · KV-Cache Memory Limits

Full multi-head attention exceeded GPU VRAM during generation at 2k context. Implemented 6:1 GQA compression, retaining accuracy while slashing VRAM 6×.

03 · Gradient Explosion Early

Replaced post-LayerNorm with Pre-RMSNorm and a 2,000-step linear learning rate warmup to prevent early training divergence without heavy weight decay.

CodeSensei — 5-Agent Distributed Intelligence

Agentic AI · Sub-90s Synthesizer

Orchestration & Agent Roles: Monolithic code reviewers fail because structure, security, runtime, behavior, and impact demand fundamentally opposing analytical perspectives. CodeSensei deploys five autonomous agents in parallel: 01 Structure (AST hierarchies & cyclic dependencies), 02 Behavior (control flow paths & side effects), 03 Risk (race conditions, unhandled exceptions & sanitization), 04 Execution (runtime memory allocations & hot loop costs), and 05 Impact (blast radius & breaking downstream changes).

Deterministic Synthesizer: Agent outputs feed into a strict JSON consensus engine. The Synthesizer cross-references findings against confidence thresholds and resolves contradictory recommendations (e.g. abstraction depth vs. runtime overhead) before generating an interactive unified code review.

LedgerLens — AI Financial Forensic Investigation

FinTech AI · ReAct Agent

Pipeline Architecture: LedgerLens tackles high-stakes financial investigations through a 6-stage evidence pipeline: 01 Reconcile (aligning ledger transactions across banking, ERP, and payment gateway feeds), 02 Anomaly Detection (unsupervised statistical clustering and Benford's Law distribution analysis), 03 Policy Engine (verifying against regulatory limits and AML rules), 04 Case Bundler (corroborating micro-events into single investigation cases), 05 Hypothesis Engine (ranking plausible fraud/error scenarios), and 06 ReAct Agent (investigating transaction logs via read-only SQL queries).

Deterministic Grounding: To guarantee that zero hallucinated figures pollute audits, the LLM is prohibited from calculating totals directly. It formulates investigative hypotheses, executes deterministic SQL queries, and records observations with cryptographic audit logs.

TalkToWeb — Closed-Loop Autonomous Browser Agent

Autonomous Execution · Self-Healing DOM

Plan-Observe-Act Closed Loop: TalkToWeb transforms unstructured natural language commands into browser actions through an iterative, feedback-driven execution loop. The agent parses user intent, breaks it down into sequential sub-goals, targets DOM elements using accessibility tree mappings (ARIA names and roles), and executes mouse/keyboard primitives via Playwright. After every action, it captures the mutated page state to verify expected outcomes before continuing.

Self-Healing & Resilience: When websites display unexpected cookie consent banners, Captchas, layout mutations, or dynamic React re-renders, TalkToWeb detects action failure, inspects the updated visual and DOM hierarchy, and dynamically replans intermediate steps to achieve the objective without human intervention.

Key Engineering Hurdles Solved

01 · Brittle CSS & XPath Selectors

Modern single-page applications generate random hashed classes on every build. Solved by replacing CSS selectors with semantic accessibility tree nodes and ARIA labels.

02 · Asynchronous DOM Race Conditions

Agents clicked buttons before hydration finished, resulting in missed actions. Built a custom network-idle and mutation watcher that verifies DOM element responsiveness before action dispatch.

03 · Unexpected Popups & Overlays

Modal dialogs trap cursor focus and abort scripts. Implemented a popup interrupt detector that intercepts z-index overlays, dismisses them safely, and resumes the active execution plan.
